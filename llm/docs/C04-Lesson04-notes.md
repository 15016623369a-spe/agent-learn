# C04 Lesson04 · Token 预算与信息取舍

给输出预留空间后，输入上限等于课堂总预算减去预留。程序用与请求匹配的聊天模板格式化消息，再数分词得到的 `input_ids`。本课完整消息正文有 1731 个字符，加助手回复起始标记后得到 745 个 Token，去掉该起始标记后是 742 个。生产环境需按目标模型与接口核对限额。 [Hugging Face 聊天模板](https://huggingface.co/docs/transformers/v5.20.2/chat_templating)

课堂策略先保留系统规则、当前问题、分组口径 H01、单位冲突两侧 D01/D03 和“尚未查询”的 T01。超限时先移除本场景用不到的注入教学样例 D02，再移除无关排版历史 H02。每轮重建来源索引和消息并重新计数。必需资料仍放不下时，返回 `over_budget` 和 `messages=None`。

预留输出 120 时，课堂实测如下。

- 总预算 1000，输入上限 880，完整输入 745 直接通过。
- 总预算 700，输入上限 580，输入依次为 745、662、580，移除两条可选资料后恰好通过。
- 总预算 520，输入上限 400，必需资料仍需 580，停止发送。

代码使用来自 C03 缓存的 Qwen/Qwen2.5-0.5B 固定版本 `060db6499f32faf8b98477b0a26969ef7d8b9987`，只加载分词器和模板。预算由课堂设置，实测范围是单个文本请求的输入长度与上下文取舍。
