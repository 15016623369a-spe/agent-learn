1. **聊天里先上课。** 从同一个办公分析案例出发，说清这节课完成哪段功能、输入输出是什么、失败时用户看到什么。把紧密相关的概念放在一节内讲，例如工具参数、分发和 SQL 同课。
2. **提供一份可运行的课堂实现。** 给出明确运行入口和示例输入，讲解关键函数及其职责。优先复用前面的代码，保留用户已有实现与学习注释。日常课堂代码放在用户指定的 `/Users/jace/agent学习/llm/` 下，新模块可用模块子目录避免与 C04 文件同名。沿用 Conda `fde`，先检查现有依赖。
3. **现场运行并交代证据。** 至少跑一个正常例、一个边界例和一个失败例。给出实际输出、状态、调用次数或其他适用指标。分别注明教学样例、实际工具执行与真实模型调用的验证范围。
4. **集中留作业。** 四题尽量落在同一份课堂代码上，覆盖正常、边界和失败。按既有约定，索要答案表示已私下完成后对照，参考答案明确标注来源。更新进度时分别记用户确认、助手补录和实际验证。
5. **明确要求同步时整理发布。** 同步当课代码、关键知识点、作业或题解、验证输出、逐课交接和 README 索引。按模块放在指定仓库，核对远端分支和提交。逐课交接至少写「本课做到什么、如何复跑、还有什么未验证、下一课复用什么」。

## C05 首课交付与验收

建议用 Python 标准库 SQLite 和公开可复跑的固定订单样例。一个课堂脚本串起「结构化参数 → 参数校验 → 分发查询 → SQL 聚合 → 工具结果」。先在本课独立跑通，接回报告流程和工具可靠性在 C05 后续与 C06 完成。

- **输入和 SQL。** 明确时间范围、时间字段、时区口径和按下单时所属部门分组。时间采用左闭右开，统计已支付订单。用参数占位符绑定日期和筛选值，以整数分求和。
- **工具输出。** 成功结果包含 `source_id`、`execution_status: succeeded` 与 `totals_fen`，可承接 C04 的 T01。查到零笔使用空汇总 `{}`。参数无效或查询失败返回明确错误，保留状态，后续可据此决定补信息、等待或停止。
- **首课验收。** 正常样例能交代固定数据的预期金额并实测一致。时间边界与空查询有独立用例。无效参数在查询前被拒绝。后续接入 C04 报告流程时，复跑缺资料、口径冲突、查不到结果和金额不符的既有用例。
- **C05 后续和 C06。** 把 SQL 查询接回 C04 的报告流程，逐步加入权限、超时、隔离和有限重试，交付受控计算工具 v0.1。下一阶段依次做 C07–C10 的 RAG、引用和评估 v0.2，C11–C15 的 Agent 循环、状态与人工审批 v0.3，以及 C16–C19 的 LangGraph、部署、安全和可演示 v1.0。
